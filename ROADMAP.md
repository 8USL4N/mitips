# ROADMAP: Экспертная система по инфекционным заболеваниям (учебный MVP)

> Стек: `Python 3.12 + FastAPI + React + Docker Compose`  
> Цель: за 1–2 недели собрать демонстрационно-готовую систему с прозрачной логикой и редактором базы знаний.  
> Формат проекта: учебный, не для клинического применения.

---

## 1) Рамки проекта

### Что делаем (MVP)
- Веб-приложение с 2 разделами: `Решатель` и `Редактор знаний`.
- Хранилище знаний в `JSON` с возможностью редактирования через UI.
- Решатель, который формирует план лечения и объяснение по симптомам.
- Полный запуск одной командой: `docker compose up --build`.

### Что НЕ делаем в MVP
- Подключение к реальным медицинским БД.
- Клиническую валидацию и медицинскую сертификацию.
- Сложную авторизацию/роли (кроме минимальной защиты редактора при необходимости).

### Обязательный дисклеймер
- В интерфейсе и README должно быть явно указано:  
  `Система носит учебный характер и не является медицинским сервисом для постановки диагноза или назначения лечения.`

## 2) Уточнение логики решателя (важно)

Чтобы не было двусмысленности, фиксируем два режима:

1. `MVP-режим (обязательный)`: `validate_selected`
- Пользователь выбирает диагноз.
- Система проверяет соответствие введённых симптомов эталону.
- Возвращает: лечение, шаги, объяснение совпадений/расхождений.

2. `Расширение (желательный)`: `rank_all`
- Пользователь вводит симптомы без выбора диагноза.
- Система ранжирует все диагнозы по score.
- Возвращает `top-3` + объяснение по каждому.

На защите достаточно `validate_selected`, но в roadmap сразу закладываем путь к `rank_all`.

## 4) Технические требования

### Backend
- FastAPI + Pydantic v2.
- Валидация входных данных через схемы, без `dict` в публичных endpoint.
- Централизованная обработка ошибок (`HTTPException` + понятные сообщения).
- Атомарная запись JSON:
  - запись во временный файл,
  - затем `replace`.
- Блокировка записи (thread lock) для защиты от гонок при одновременных запросах.

### Frontend
- React + Vite + Axios + React Router.
- Все вызовы API вынести в `api/client.js`.
- Обработка состояний: loading, error, empty.
- Формы с базовой валидацией до отправки.

### Docker
- `docker compose up --build` поднимает всё с нуля.
- Персистентность JSON через volume `./backend/data:/app/data`.

### UX
- Русский интерфейс.
- Таблица объяснений с подсветкой совпадений.
- Адаптивность на ноутбуке и мобильной ширине.

## 6) Минимальный API-контракт

### Solver
- `POST /api/solver/solve`
- Request:
```json
{
  "diagnosis": "Холера",
  "patient_values": {
    "Температура тела": 36.5,
    "Характер стула": "1",
    "Боль в животе": "0"
  }
}
```
- Response:
```json
{
  "diagnosis": "Холера",
  "icd10": "A00",
  "treatment_name": "Лечение холеры",
  "actions": ["..."],
  "explanation": [
    {
      "characteristic": "Температура тела",
      "expected": "35.0–37.0 °C",
      "actual": 36.5,
      "match": true
    }
  ]
}
```

### Knowledge
- `GET /api/knowledge/`
- `GET /api/knowledge/diagnoses`
- `GET /api/knowledge/characteristics`
- `GET /api/knowledge/treatments`
- `POST /api/knowledge/diagnoses/{name}`
- `PUT /api/knowledge/diagnoses/{name}`
- `DELETE /api/knowledge/diagnoses/{name}`
- `PUT /api/knowledge/treatments/{name}`

## 7) Критерии готовности (Definition of Done)

### Функционально
- Все 9 диагнозов доступны и отрабатывают в решателе.
- По каждому диагнозу возвращается корректный список действий.
- Редактор позволяет менять диагнозы и шаги лечения.
- После изменения БЗ результат решателя обновляется без ручного вмешательства.

### Технически
- Проект запускается на чистой машине через Docker.
- JSON сохраняется между рестартами контейнеров.
- Есть минимум 6–8 backend-тестов (solver + API).

### UX/демо
- UI на русском.
- Видны объяснения совпадений по симптомам.
- В демо есть сценарий "изменили БЗ -> сразу увидели новый результат".

## 8) Риски и меры

- Риск: поломка JSON при записи.  
  Мера: атомарная запись + резервная копия `.bak`.

- Риск: гонка при одновременном редактировании БЗ.  
  Мера: lock на операции записи.

- Риск: несогласованность схем (`characteristics`, `diagnoses`, `treatments`).  
  Мера: валидация ссылочной целостности перед `save`.

- Риск: завышенное ожидание "настоящей диагностики".  
  Мера: явный дисклеймер в UI и README.
